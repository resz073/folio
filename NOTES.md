## PDF pipeline (done)
- src/js/44-paint.js: PaintSession walks the sheets and the editor and paints from the live layout, using Range rects per word.
  - Pixel diffs against the DOM are about 0.003–0.06% (tests/paint1.py, tests/paint2.py).
  - Decorations follow Chromium's rules: thickness floor(f/10); underline top at base + max(1, ceil(raw/2)); line-through top at base − asc/3 − raw/2, with +0.5 when the decoration comes from a block.

- src/js/45-pdf.js: the writer.
  - Page images are Flate with PNG Up prediction, 4-bit grey when the page has no colour, and fall back to JPEG for photo-heavy pages.
  - Invisible text layer: a glyphless TrueType font, Type0 Identity-H, ToUnicode, DW 500, Tz per word.
  - Reading order is header, then body, then footer. Links become URI annotations.
- Validated with pdftotext (English and Bangla), qpdf --check, pypdf and pdfjs-dist. Exports are 1.5x, 2x (default) or 3x.

## Tables, borders and shading (new)
- src/js/15-tables.js: tables are edited as a grid model `{ rows, nr, nc, cells: [{ el, r, c, rs, cs }], widths }`.
  - `model()` reads it, `rebuild()` writes rows, spans and column widths back (filling holes with cells cloned from a neighbour; `compact` drops rows or columns no cell starts in).
  - Built on it: `splitInModel` / `splitCells` (any cell into n × m; a merged cell's rows must divide), `insertRowsAt` / `insertColsAt` (copy the neighbour's formatting and merges), `insertCells` (shift right adds grid columns and widens the left neighbour in other rows; shift down moves cells down and adds rows), `deleteCells` (shift left / up, blanks fill the end), `splitTable`, `distributeRows`. Selecting cells is in 15b-cellsel.js (see the cell selection section below).
  - `gridlines()` draws dashed lines in #overlay where a table edge has no visible border (View Gridlines, Prefs.gridlines). Preset tables are skipped unless cells set their own borders.
- src/js/18-borders.js: the border model. A border is `{ style, width (pt), color }` or null.
  - Styles are the CSS ones (solid, dotted, dashed, double, groove, ridge, inset, outset), mapped to Word's single, dotted, dashed, double, threeDEngrave, threeDEmboss, inset, outset. A double's CSS width is three times Word's width.
  - A table with its own borders has class `tbl-bd` and CSS variables `--bt --bb --bl --br --bh --bv`. doc.css applies the inside ones to every cell and the outside ones to cells tagged by `Tables.markEdges()` (`data-edge`, refreshed at the start of every layout and stripped by cleanHTML).
  - A cell's own borders are inline styles. `Borders.applyCells` also sets the neighbour across each outside edge, so the shared line really changes (collapsed borders).
  - Diagonals: `data-dd` (tl2br) and `data-du` (tr2bl). Shading patterns: `data-shd` (Word's w:shd val), `data-shdc` (pattern colour), `data-shdf` (fill). `decoSync()` turns them into background layers (an SVG diagonal stretched over the cell, a 6 px SVG pattern tile). Percent patterns show as a blended colour, as Word does.
  - Paragraph borders are inline, with padding as Word's w:space and `--bbtw` for the line between paragraphs. `markParaGroups()` (run with layout) joins consecutive paragraphs with the same borders into one box (`data-bj`, `--bjg`, `--pb0`); the joining CSS is off during .docx export so the stored values are read.
  - Text borders and text shading wrap the selection in one span per paragraph (`span[data-tb]`, `span[data-ts]`).
  - The pen (Prefs.pen) is used by Draw Table, Border Painter and the Borders buttons. `Borders.quick(kind)` toggles edges like Word's Borders menu, on cells in a table and on paragraphs elsewhere.
- src/js/19-tabledraw.js: Draw Table, Eraser and Border Painter (TDraw).
  - A capture pointerdown on #paper. Drag a box outside tables for a new one-cell table. A straight line across cells splits them (new grid row or column, with row heights from the drawing). A line on an existing edge paints it. A slanted line inside a cell adds a diagonal.
  - The eraser merges two cells when they line up, otherwise removes the line. Esc or any key ends the tool.
- src/js/54-tabledialogs.js: Split Cells, Insert Cells, Delete Cells, and Borders and Shading (Borders, Page Border, Shading tabs; Apply to Text / Paragraph / Cell / Table; clickable preview with edge buttons including inside and diagonals; paragraph and page Options).
- Page border: `S.doc.page.border` is false, true (old documents) or `{ style, width, color, sides, shadow, from: 'page'|'text', m: {t,b,l,r} pt, show: 'all'|'first'|'rest' }`; see normPageBorder() and pageBorderHtml().
- Ribbon: one contextual tab, Table Design (the user asked for no second "Layout" tab, since the page Layout tab exists). Groups: Table (Select, View Gridlines), Draw (Draw Table, Eraser), Rows & Columns (Delete, Insert Above/Below/Left/Right, launcher Insert Cells), Merge (Merge Cells, Split Cells, Split Table), Cell Size, Alignment, Table Styles (Shading, Styles, Header Row, Banded Rows), Borders (Border Styles, line style/weight, pen colour, Borders, Border Painter, launcher Borders and Shading).
- UI.fitRibbon(): groups with a `collapse` order show their stacked buttons as icons (lowest order first) when the tab is wider than the window, only if that makes it fit. Table Design fits at 1280px; Merge keeps its labels longest.
- .docx: tblBorders from the table variables and tcBorders only for a cell's own sides; tl2br/tr2bl; w:shd patterns on cells, paragraphs and runs; pBdr with space, between and shadow; run w:bdr; trHeight; pgBorders with offsetFrom, display and shadow. The reader resolves table-style borders (basedOn chain and the default table style) and reads all of these back.
- Paste keeps cell, paragraph and text borders from Word HTML (`declBorders`) and table variables, diagonals and patterns from Folio's own HTML.
- PDF painter: 3-D styles use Chromium's colours (calibrated: dark = colour × (v−0.33)/v, black lightens to #545454; in collapsed tables inset draws as ridge and outset as groove); diagonals, patterns (from the same SVG tile), solid offset shadows, inline (text) borders, and collapsed-border conflicts (the wider, then stronger style wins; ties go to the top/left cell).

### Selecting table cells, like Word (2026-10-18, third session)
User reported: can't select a single column/row; can't align text in one column; copying n cells and pasting over n selected cells put everything in one cell.
Cause: `Tables.sel` (a rectangle drawn as an overlay) existed, but formatting, copy and paste all used the browser's own selection, which runs row by row through a table.
- src/js/15b-cellsel.js (extends Tables; loads after 15-tables.js). `Tables.sel = { table, r1, c1, r2, c2 }` (grid slots), `anchor` and `head` cells.
  - While cells are selected, the browser selection is a collapsed caret "parked" at the start of the anchor cell (`park()`, `isParked()`). `#editor.cellsel` hides the caret and ::selection, and `.cell-hl` divs in #overlay show the cells (`refreshHL`).
  - `onSelChange(r)` (from onSelectionChange): a range that isn't the parked caret ends cell mode, unless it is outside the editor (focus in the font box or a dialog). A text selection from one cell into another becomes a cell selection.
  - Mouse (`onMouseDown`, `zoneAt`, `zoneDown`, `drag`): a drag that reaches another cell selects cells, and going back to the first cell or off the table returns to text selection. Shift+click extends.
  - Word's selection arrows (`CELLSEL_CURSORS`, SVG cursors set by `hoverCursor`):
    - 6px band above the first row selects a column (drag across for more)
    - 28px left of a row selects the row
    - strip inside a cell's left edge (3px…padding) selects the cell
    - the left-edge column-resize zone is now <3px
  - Keys (`onKeyDown`, first in onEditorKeyDown):
    - Shift+arrows move the head (`moveHead`)
    - arrows, Home, End, PageUp/Down end the selection at its start or end
    - Escape ends it
    - Delete/Backspace empty the cells, keeping each first paragraph's formatting (`clearContents`; Track Changes marks deletions)
    - typing empties the cells and types into the first one (`typeOver`)
    - Tab ends it and moves on
  - Without a cell selection, `shiftOutOfCell` probes with Selection.modify whether a Shift+arrow would leave the cell. If so, it selects the cell and its grid neighbour, because Chrome's own Shift+Down at the end of a cell goes to the next cell in DOM order.
  - Undo/redo: `saveSel()` adds `cells` (`serialize()`: table index plus slots) and `restoreSel()` calls `Tables.restore()`. So undo, redo and the paste chip bring the cell selection back.
- Formatting acts on the selected cells:
  - `selectedBlocks()` with no range → `Tables.selBlocks()`. This covers alignment, styles, spacing, the paragraph dialog, indent and Format Painter.
  - `applyInline` uses `cellTexts()`.
  - `toggleInline` uses per-cell execCommand. It turns the format on for all cells unless every cell already has it.
  - `changeCase` and `clearFormatting` (now `clearFormattingIn(r)` per cell via `forEachCell`) handle cells too.
  - `toggleList` makes one list per cell.
  - Shading, borders, vertical alignment and the row/column commands already used `selectedCells()`.
  - The mini toolbar shows over selected cells (`showMini`). `clearSel` hides it.
- Copy/Cut (`onCopy` → `copyCells`):
  - HTML is a table of only those cells, marked `data-folio-cells`, with px colgroup and data-fit fixed.
  - Text is Excel-style TSV (`toTSV`): cells with tabs, newlines or a leading quote are quoted.
  - The ribbon Copy/Cut buttons select the anchor cell's contents first (`execClip`), because the browser won't copy from a collapsed selection.
- Paste (`doPaste` → `Tables.pasteCells`, not for drops), like Word's Overwrite Cells and Excel. `clipGrid()` reads the clipboard:
  - a lone HTML table (Folio, Excel, Sheets, Word)
  - TSV text (`parseTSV`, Excel quotes) when cells are selected or the HTML held cells ("Text only")
  - with cells selected: formatted text, one value or a paragraph per row
  At a caret, plain text with tabs and one value stay an ordinary paste, as in Word.
  How it fills:
  - The block starts at the top-left selected cell (or the caret cell) and adds rows at the bottom if needed. Columns that don't fit are dropped, with a toast.
  - It repeats over a selection that is a whole multiple of the block, so one value fills every selected cell.
  - Slots inside a merged target cell are skipped.
  - Afterwards the pasted cells are selected.
  `fillCell` modes:
  - 'keep': the source paragraphs
  - 'merge' and pieces of a paragraph (`inline`): the inline content in a copy of the cell's first paragraph, so the cell keeps its alignment
  - 'text': lines
  - Track Changes: del + ins
  A one-cell table pasted at a caret in a cell, or copied from Folio, pastes as its contents (`unwrapLoneCell`).
- Sanitizer:
  - Excel HTML has its simple class rules (.xl65{…}) inlined (`inlineClassRules`).
  - Every pasted table cell passes its own text formatting (no background) and alignment (style or align=) to its paragraphs. This applies to all table pastes, not only Excel.

- src/js/13b-decimal.js (DecAlign), Word's decimal tab:
  - Storage: a paragraph gets `data-align="decimal"` and `text-align:right` (`alignBlock(b, 'decimal')` in 13-blocks.js; any other alignment removes it, and so does Clear Formatting).
  - Layout: `DecAlign.layout()` runs each layout pass with Tables.markAll/markParaGroups. The alignment point is before the last digit-dot-digit, else after the last digit, else at the end; Latin, Bangla and Devanagari digits count. It then sets `--decpad` = groupMax − tail.
  - CSS: doc.css `[data-align="decimal"] { padding-right: var(--decpad) !important }`. Multi-line paragraphs get no padding.
